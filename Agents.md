# Agents.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A collection of [Dev Container Templates](https://containers.dev/implementors/templates), published to GHCR as `ghcr.io/pawel-kow/devcontainer-templates/<id>`. It started from `devcontainers/template-starter`, and the root README is still that starter's authoring guide (it mentions the removed `hello` and `color` samples). The only template now is `python-node-gh-claude`.

The root `.devcontainer/` is the environment for working on this repo. It is not a template.

## Layout and conventions

- `src/<id>/` holds a template: `devcontainer-template.json` (metadata and `options`), `.devcontainer/devcontainer.json`, and an optional `NOTES.md`. The folder name must equal the `id`, and ids can't contain `+` (invalid in OCI names).
- `src/<id>/README.md` is auto-generated by the release workflow from `devcontainer-template.json` plus `NOTES.md`. Edit `NOTES.md`, not the README.
- Options are referenced in template files as `${templateOption:<optionName>}`. Every option needs a `default`, because `build.sh` substitutes the defaults with `sed` across all files in the template and fails if one is missing.
- `test/<id>/test.sh` sources `test-utils.sh` (the `check` / `reportResults` helpers). The smoke test copies it, along with `test/test-utils/`, into the container as `test-project/`.
- A new template must also be added to the `filters` list in `.github/workflows/test-pr.yaml`. The paths-filter there is hard-coded per template, so a template missing from it is never tested in CI.

## Commands

```bash
# Build the template in a dev container (substitutes default options, runs `devcontainer up`)
./.github/actions/smoke-test/build.sh <template-id>
# Run test/<id>/test.sh inside it, then remove the container
./.github/actions/smoke-test/test.sh <template-id>
```

Both are run from the repo root and need Docker and the `devcontainer` CLI. `build.sh` installs the CLI if it's missing. The smoke test copies the template to `/tmp/<id>`. To run a single check, `devcontainer exec` into that container and run `test-project/test.sh`, or call the command directly.

## Release

`.github/workflows/release.yaml` is manual (`workflow_dispatch`, `main` only). It publishes every template under `src/`, regenerates the READMEs, and opens a docs PR. This needs the repo setting "Allow GitHub Actions to create and approve pull requests". New GHCR packages are private until set to public in the package settings. Bump `version` in `devcontainer-template.json` for each release of a template.
